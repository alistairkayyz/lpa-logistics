# Architecture Context

## Stack

| Layer      | Technology                                    | Role                                              |
| ---------- | --------------------------------------------- | ------------------------------------------------- |
| Framework  | TanStack Start (React 19 + TypeScript)         | SSR/file-based routing framework                  |
| UI         | Tailwind CSS v4 + shadcn/ui (Radix primitives) | Styling and accessible component primitives       |
| Animation  | GSAP 3 + @gsap/react                           | Hero entrance and contact form micro-animations   |
| Bundler    | Vite 8 + @tailwindcss/vite + LightningCSS      | Dev server, builds, CSS transform                 |
| SSR server | Nitro (vercel preset)                          | Produces Vercel Build Output API at `.vercel/output` |
| Deployment | Vercel                                         | Hosting and edge delivery                         |
| Data fetch | TanStack Query v5                              | Provided in root layout; unused for now           |

## System Boundaries

- `src/routes/` — File-based route modules; each file is a page. `__root.tsx` defines the HTML shell, global head, and root context provider.
- `src/components/` — Shared UI. `sections/` holds homepage/page section components; `ui/` holds shadcn/ui primitives (do not edit directly).
- `src/lib/` — Utilities, server config, error capture. `api/` for future server functions.
- `src/assets/` — Local static assets (images, logos) imported directly in components.
- `src/styles.css` — Single global stylesheet. Tailwind v4 source, CSS custom properties, font-face declarations, utility definitions.

## Storage Model

- **No database** — This is a purely static/SSR marketing site. No persistent data storage.
- **Assets**: Images and logos are local files under `src/assets/`, imported via Vite and bundled at build time.

## Auth and Access Model

- No authentication. The site is entirely public.
- No ownership or access control model required.

## Invariants

1. No server-side data fetching or mutations — all pages are static renders with no database or external API calls.
2. `components/ui/*` files are generated by the shadcn/ui CLI — do not hand-edit them.
3. The Nitro `vercel` preset must remain active at build time; changing the preset will break Vercel deployment.
4. All CSS tokens must be defined in `src/styles.css` as CSS custom properties — no hardcoded hex values in components.
5. The contact form submit handler is currently client-side only (sets `sent = true`); no actual email is sent.
